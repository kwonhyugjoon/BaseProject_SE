# Actor와 Scene Graph

화면 객체는 `Actor`로 배치하고 `SceneGraph`를 통해 갱신·그리기를 수행한다. 도형을 매번 임시 객체 목록으로 조합하여 정렬하던 코드 대신, 지역을 구성할 때 만들어지는 지속 노드를 사용한다.

## 역할

- `Actor`: 이름, 부모·자식, 위치, 표시 여부, 갱신 활성 여부, 렌더링 레이어, 업데이트/그리기 콜백.
- `SceneGraph`: 노드 소유권, 순회, 갱신, 레이어와 쿼터뷰 깊이 정렬, 월드/UI 그리기 분리.
- `Renderer`: Actor 콜백이 요청한 도형·모델·문자를 GPU로 전달한다. 게임 객체의 수명과 배치는 관리하지 않는다.
- 게임 데이터: 체력·경험치·퀘스트·충돌 규칙을 유지한다. 주민·집·나무·동물·플레이어·적의 위치는 Actor가 소유한 `Point`를 참조한다. 화면용 위치 복사본을 별도로 두지 않는다.

## 그래프 구성

```text
Scene
├─ World
│  ├─ Ground / Terrain
│  │  ├─ 지면 구역 (튜토리얼 8×8 월드 단위 / 사냥터 8×8 타일)
│  │  ├─ 밭 → 작물
│  │  └─ 호수 → 갈대, 물빛
│  ├─ Houses / People / Animals / Enemies
│  │  └─ 개별 Actor → 그림자, 체력 표시
│  ├─ Trees
│  │  └─ 나무 구역 (16×16 월드 단위) → 개별 나무 Actor → 그림자
│  ├─ Player → 그림자, 무기
│  ├─ Relics / Decorations / Drops
│  └─ Effects → 부유 입자, 목표 표시
└─ UI
   └─ HUD (패널·문자·미니맵 등을 그리는 복합 Actor)
```

집의 창문과 지붕, 캐릭터의 팔다리처럼 하나의 모델을 이루는 도형은 해당 Actor의 구성 요소다. UI의 개별 글자나 픽셀을 별도 Actor로 만들지는 않는다.

2026-09-30 확장에서는 지면 타일을 구역 Actor의 구성 요소로 묶었다. 사냥터의 나무·바위는 구역의 자식 Actor로 유지하며 화면 밖 구역은 자식까지 그리기에서 제외한다. 충돌은 기존 타일 격자를 사용한다.

## 위치와 제어

```cpp
Actor& group = scene.World().AddChild("Village", {20, 30});
Actor& house = group.AddChild("House", {3, 2});

// 집의 월드 위치는 (23, 32).
group.SetLocalPosition({25, 30}); // 집과 그 자식도 함께 이동.
house.SetWorldPosition({30, 35});
group.SetVisible(false);         // 하위 객체를 포함해 그리기 중단.
group.SetEnabled(false);         // 하위 객체를 포함해 업데이트 중단.
```

- `AddChild`와 `SetLocalPosition`은 부모 기준 좌표, `SetWorldPosition`과 `Position`은 월드 좌표다. UI 트리에서는 좌표 단위가 화면 픽셀이다.
- 현재 필요한 변환은 **위치 이동**이다. 회전·스케일 행렬, 3D 계층 변환이나 에디터는 추가하지 않았다.
- 기존 이동 코드와 충돌 코드의 호환을 위해 `Position()`의 참조를 사용할 수 있다. 이 참조를 수정한 경우 다음 그래프 순회에서 자식 위치를 동기화한다. 즉시 반영이 필요하면 위치 설정 함수를 사용한다.
- `SetVisible`은 렌더링, `SetEnabled`는 업데이트를 제어한다. 숨김 자체가 충돌 지형을 제거하는 동작은 아니다.
- `SetDrawCull`의 조건이 거짓이면 해당 Actor와 자식을 그리기 수집·정렬에서 제외한다. `IsVisible`과 갱신 활성 상태는 바꾸지 않는다. 마을의 화면 밖 나무 구역과 집·나무에 적용하며, 구역 범위는 현재 Actor 위치를 기준으로 갱신한다.
- 첫 레벨 지형은 생성된 타일 격자가 충돌의 기준이다. 타일을 이동해 맵 구조를 편집하려면 격자 데이터도 함께 바꿔야 한다. 이번 변경은 지형 편집 기능을 포함하지 않는다.

## 수명과 처리 순서

- 부모가 `unique_ptr`로 자식을 소유한다. 노드는 복사되지 않으며 Actor 참조는 해당 노드를 제거하기 전까지 유효하다.
- 업데이트 중 생성된 Actor는 다음 업데이트부터 순회하며, 같은 프레임의 그리기에는 참여할 수 있다.
- 순회 중 제거/전체 자식 삭제를 요청하면 남은 콜백을 건너뛰고 순회 종료 후 제거한다. `World`와 `UI` 루트는 보호한다.
- 게임 데이터가 노드를 참조하는 경우 데이터를 먼저 제거한 뒤 노드를 정리한다. 튜토리얼 재시작과 사냥터 재생성에 이 순서를 적용했다.
- 플레이어·주민·적처럼 게임 데이터가 참조하는 노드를 그래프 API로만 삭제하면 참조가 무효화된다. 삭제는 해당 게임 데이터의 정리 경로에서 수행한다.
- 적 처치 시 적 Actor를 숨겨 그림자와 체력 표시도 함께 숨긴다. 재등장하면 다시 표시한다. 전리품 획득 시 게임 데이터와 Actor를 함께 제거한다.
- 월드는 Ground → Shadow → World → Effect 순서로 그린다. World 레이어는 `x+y`로 안정 정렬해 깊이가 같으면 생성 순서를 유지한다.
- 월드 그리기 → 기존 후처리 → UI 그래프 그리기 순서를 유지한다.

### 순회 비용 (2026-09-28)

- 지면·그림자·이펙트·UI는 트리 순서를 유지하며 깊이 정렬에서 제외한다. World 레이어만 수집 시 계산한 깊이와 순번으로 정렬한다.
- 그래프가 레이어별 버퍼를 재사용한다. 정렬 비교 함수에서 부모 탐색이나 위치 동기화를 수행하지 않는다.
- 위치 동기화 수집은 부모부터 한 번씩 진행하며, 업데이트 콜백이 있는 노드만 갱신 목록에 넣는다.
- 삭제 요청이 표시된 가지에만 정리를 수행한다. 삭제가 없는 프레임에서는 전체 트리 삭제 검사를 생략한다.
- 그리기 목록 수집 당시 숨겨진 가지는 제외한다. 그리기 콜백에서 다시 표시한 노드는 다음 그리기 순회부터 반영한다.
- 이 변경은 정적 검토만 수행했으며 실제 프레임 개선량은 측정하지 않았다.

## 검증과 실행 확인

2026-09-28 이동 표시 보정: 두 지역의 카메라는 플레이어 위치를 즉시 따른다. 정지 후 카메라가 뒤늦게 움직이는 지연 추종을 제거했다. 나무 가림 투명도는 거리 경계에서 연속적으로 전환하며, 캐릭터 스프라이트는 옷 색상을 해석한 뒤 알파를 고려해 픽셀 사이를 보간한다. 실제 잔상·끊김 개선 여부는 빌드와 플레이 확인이 필요하다.

`tests/SceneGraphTests.cpp`에 부모·자식 이동, 직접 위치 참조 수정, 표시/활성 상속, 레이어 상속, 순회 중 생성·삭제 및 재생성 검사를 작성했다. 2026-10-14 Debug x64 독립 컴파일·실행에서 통과했다. 같은 날 그리기 제외 조건이 자식 렌더를 막으면서 업데이트·표시 상태를 유지하는지도 CPU 전용 비교 프로그램으로 확인했다. 실제 게임의 화면·FPS 확인과는 별개다.

필요 시 Visual Studio 개발자 명령 프롬프트에서 저장소 루트 기준으로 독립 테스트를 실행할 수 있다. 게임이나 OpenGL 창을 실행하는 테스트는 아니다.

```bat
set "ACTOR_TEST_REPO=%CD%"
pushd "%TEMP%"
cl /nologo /EHsc /std:c++14 /utf-8 "%ACTOR_TEST_REPO%\tests\SceneGraphTests.cpp" "%ACTOR_TEST_REPO%\SimpleGame\Actor.cpp" "%ACTOR_TEST_REPO%\SimpleGame\SceneGraph.cpp" /Fe:BaseProjectSceneGraphTests.exe
if not errorlevel 1 BaseProjectSceneGraphTests.exe
popd
```

게임에서는 튜토리얼 이동·충돌·대화·호수 선택, R 재시작, L 사냥터 진입/귀환, 적 사망/재등장, 전리품 획득, 그림자·UI 순서와 숲에서의 프레임을 확인한다. 노드 변환은 집이나 나무 그룹의 위치를 설정해 자식 그림자와 함께 움직이는지도 확인한다.
