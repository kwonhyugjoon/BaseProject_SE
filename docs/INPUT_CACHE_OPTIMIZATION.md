# 입력·상태 처리와 모델 캐시 보정

기준일: 2026-11-10. LEC11 변경 사항이다. 스토리 4단계의 구현과 구분한다.

## 입력과 진행 상태

- Space를 한 프레임 사이에 눌렀다 떼어도 다음 이동 계산 단계가 공격 요청을 소비한다. 유지 입력은 기존 공격 간격으로 반복된다. 지도·가방·대화·일지·일시정지·포커스 상실·지역 이동에서는 대기 공격도 취소한다.
- 적의 이동 여부는 프레임 전체에서 누적한다. 마지막의 짧은 나머지 시간 단계가 이미 수행한 이동을 정지 애니메이션으로 덮어쓰지 않는다. 이동량이 없는 단계에서는 방향도 바꾸지 않는다.
- 마을 일시정지의 R은 **새 게임**이다. 튜토리얼·선택·지역 기록과 함께 레벨·경험치·체력·동전·재료·처치를 초기화한다. 마을 모델 캐시는 재사용한다.
- 전투 지역에서 사망 후 R은 기존 원정 재시작이다. 성장과 전리품은 초기화하고 일지·선택은 보존한다. 회복·부활의 본편 비용 규칙을 새로 확정한 것은 아니다.
- 지도·가방·사망을 포함한 실제 전투 시뮬레이션 정지 조건을 모니터와 공유한다.

## CPU 반복 작업

SceneGraph는 갱신 콜백 목록을 재사용한다. 노드 추가·제거, 콜백 유무 변경, 새로운 위치 참조 대여가 생기면 목록을 다시 만든다. 순회 중 생성·삭제는 기존처럼 다음 갱신과 순회 종료 후에 반영한다. `Point&`를 직접 바꾸는 기존 사용법을 유지하기 위해 대여된 위치의 동기화는 계속 수행한다. 읽기 전용 그리기 코드는 `WorldPosition()`을 사용한다.

마을 나무는 위치를 확인하되 실제 위치나 개수가 바뀌었을 때만 충돌 격자와 구역 경계를 다시 만든다. 개별 Actor의 위치 설정·위치 참조 수정·부모 이동을 반영한다. 변하지 않은 프레임에서 격자를 비우고 채우던 작업을 줄였다. 변경 감지를 위한 위치 확인까지 없앤 것은 아니다.

Renderer의 모델 제출은 정점 복사 뒤 다시 변환하던 두 번의 순회를 한 번으로 합쳤다. 용량은 필요할 때 늘리고 그리기 순서·배칭·색상·UV는 유지한다. 정적 모델 전체를 GPU 상주 버퍼로 바꾸지는 않았다. 현재 프레임 정점 업로드는 유지하므로 해당 비용이 사라졌다고 설명하지 않는다.

합성 CPU 비교에서는 정적 노드 15,844개, 대여 위치 6,272개, 갱신 Actor 64개를 두고 같은 이전 코드와 수정 코드에 600회 갱신을 5회 실행했다. 중앙값은 이전 약 46.5ms, 수정 약 25.9ms였다. 렌더링·충돌·실제 프레임 루프를 제외한 비교이며 실제 FPS나 최저 프레임의 개선율이 아니다.

## 마을 모델과 불꽃

집과 나무의 생성된 정점을 `VillageModels`에서 공유하고 사용자 캐시 폴더의 `village-models-v1.mesh`에 저장한다. 한 번도 그리지 않은 모델은 처음 필요할 때 생성하며, 정상 종료 시 새 항목을 저장한다. 다음 실행에서는 검증한 정점을 재사용한다. 손상·크기·정점 수·비정상 수치·재질 값 검사를 통과하지 못한 캐시는 재생성한다. 캐시 저장 실패 시 현재 메모리의 모델로 계속 그린다.

집은 크기와 지붕 색, 나무는 최초 배치 시드·크기·종류로 외형을 구분한다. 나무 Actor를 이동해도 외형 시드는 유지한다. 줄기와 수관은 같은 캐시 항목의 구성 요소이며, 위치·흔들림·가림 투명도는 그릴 때 적용한다. 캐시는 게임 진행 저장 파일이 아니다.

마을의 불꽃 본체는 고정 사각형과 기존 `Material::Flame` 셰이더를 사용한다. 매 프레임 CPU에서 불꽃 실루엣을 다시 만들지 않는다. 주변 발광·불티·연기의 기존 보조 효과는 유지한다.

## 확인한 범위

- CMake Release x64 빌드와 14개 독립 검사 통과. 새 공격 입력·이동 애니메이션·초기화·모니터·개별/부모 나무 이동 회귀 검사와 캐시 손상 복구를 포함한다.
- 기존 Visual Studio 솔루션의 Debug x64 빌드 통과. 빌드 산출물은 검사 전용 임시 경로에 생성했다.
- 숨김 GLFW Core/Compatibility 렌더에서 모델 위치·색 변환, 마을·드워프 도시·고원·고룡 쉼터와 OpenGL 오류를 검사했다. 마을 모델 147개 인스턴스의 저장·재로딩 데이터가 일치했고, 두 번째 프로세스는 캐시를 다시 쓰지 않고 재사용했다. 기존 Windows 한글 출력 표본과 비교한 4,096,000개 색상 채널의 차이는 0개였다.
- 실제 플레이·외형 품질·최저 FPS와 다른 OS 실행은 사용자 확인 범위다. 먼저 Release x64에서 짧은 Space 입력, 적 이동, 지도/가방 정지 상태, 새 게임 초기화와 마을 진입을 확인한다.
